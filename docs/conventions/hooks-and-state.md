## 1. Состояние: по умолчанию — `useState`

Для масштаба этого проекта состояние нужно только в двух местах: открытие/закрытие drawer'а и форма генератора изображений (промпт/pending/результат/ошибка). Решающее правило (эскалировать только при реальной необходимости):

`useState` → `useReducer` (несколько связанных переходов состояния в одной фиче) → `useContext` (небольшое, редко меняющееся значение, нужное поддереву).

**Context/Zustand/Redux не нужны в этом проекте** — нет cross-cutting клиентского состояния, разделяемого между несвязанными частями дерева. Если такая потребность появится, решение — отдельный ADR, не де-факто добавление стора.

Для формы генератора изображений (pending/success/error) — **дискриминированное объединение состояний**, не независимые булевы:

```ts
type GenerationState =
  | { status: 'idle' }
  | { status: 'pending' }
  | { status: 'success'; image: string }
  | { status: 'error'; message: string };
```

Не `isLoading`/`isError`/`data` тремя независимыми `useState` — рассинхронизация невозможных комбинаций недопустима.

## 2. Hooks discipline (обязательно)

- **Правила хуков** — только на верхнем уровне компонента/кастомного хука; тело компонента остаётся чистым рендером (без `fetch`/`localStorage`/таймеров вне `useEffect`).
- **`useState`** — никогда не мутировать напрямую; обновление через `prev => ...` или новый массив/объект. Производные значения (например, отформатированная ссылка на стих) вычисляются в рендере, не синхронизируются через `useEffect`.
- **`useEffect`** — не передавать `async`-функцию напрямую в эффект; объявлять внутри и вызывать. Всегда убирать за собой подписки/таймеры/незавершённые запросы (`AbortController` для `fetch` — актуально для формы генератора изображений).
- **`useRef`** — для изменяемых значений, не должных вызывать перерендер (счётчики, предыдущее значение пропа, DOM-ссылки); не моделировать их через `useState`.
- Самодельное асинхронное UI-состояние (когда нужно, как в форме генератора) — дискриминированное объединение (§1), не независимые булевы.
- **Мемоизация** — только по измеренной необходимости, не по умолчанию; всегда мемоизировать `value` Context Provider, если Context вообще используется.
- **`useTransition`** — никогда не блокировать/дизейблить сам инициирующий элемент управления, пока `isPending` (кнопка «Сгенерировать» показывает состояние ожидания, но не «замирает» недоступной без обратной связи).
- **`useId`** — для SSR-safe DOM/aria id, никогда не использовать как React `key` списка.
- **Кастомные хуки** — одна забота на хук (не «god hooks»); при 3+ возвращаемых значениях — именованный объект, не массив-кортеж; никогда не возвращать JSX.

## 3. SSR-безопасность (App Router) — обязательно

**Никогда не создавать модульный singleton-стор, хранящий per-request/per-user данные** — сервер общий для всех запросов, singleton «утечёт» состояние одного пользователя в ответ другому. В этом проекте это касается прежде всего `app/api/image-generator/route.ts`: не кэшировать промпт/результат в module-level переменной между запросами — только локальные переменные внутри обработчика запроса.

Клиентский-только, не чувствительный к пользователю глобальный стор (например, тема оформления) допустим как singleton **только внутри Client Components**, никогда не импортируется в серверный код — в этом проекте такой стор не требуется (палитра фиксирована, переключения темы нет).
