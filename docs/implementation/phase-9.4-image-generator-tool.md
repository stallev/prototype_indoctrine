### 9.4.2 — `app/tools/image-generator/page.tsx`

- **Статус:** done
- **Попытки:** 1
- **Definition of Done:** браузерный тест — форма отправляет промпт на 9.4.1, показывает pending-состояние (кнопка заблокирована/индикатор) на время запроса, отображает превью результата, кнопка скачивания сохраняет файл через `<a download>` по клику; ошибка API отображается как понятное сообщение, страница не падает.
- **Описание:** `'use client'` форма — единственная клиентская страница инструмента. Не связана ссылками с навигацией по катехизису (drawer, `/topic/*`, `/q/*`). UI-задача — браузерное тестирование обязательно.
- **Конвенции:** [`../conventions/hooks-and-state.md`](../conventions/hooks-and-state.md) §1 (дискриминированное объединение `idle`/`pending`/`success`/`error`, не три независимых булевых состояния), §2 (`AbortController` на `useEffect`-очистке при уходе со страницы, `useTransition` не блокирует саму кнопку) · [`../conventions/accessibility-and-motion.md`](../conventions/accessibility-and-motion.md) §2–3 (`label`/`aria-invalid` на форме) · [`../conventions/copy-icons-fidelity.md`](../conventions/copy-icons-fidelity.md) §1 (строки формы — из `lib/messages.ts`, не инлайн).
- **Заметки агентов:** `implementer` (попытка 1): создан `app/tools/image-generator/page.tsx` (`'use client'`, единственная клиентская страница инструмента, не связана ссылками с navdrawer/`/topic/*`/`/q/*` — не редактировались `components/nav-drawer.tsx`/`app/layout.tsx`). Добавлен блок `imageGenerator` в `lib/messages.ts` (`heading`, `promptLabel`, `promptPlaceholder`, `submit`, `pending`, `download`, `downloadFileName`, `previewAlt`, `emptyPromptError`, `genericError`) — все строки формы берутся оттуда, ни одна не захардкожена в JSX. Состояние — дискриминированное объединение `GenerationState` (`idle`/`pending`/`success { image }`/`error { message }`) через один `useState`, ровно как в задаче. Pending-UX: кнопка «Сгенерировать» НИКОГДА не получает атрибут `disabled` — во время pending её текст меняется на «Генерация…» + `Loader2` (lucide, `animate-spin`, `aria-hidden`), повторный клик во время pending игнорируется логическим ранним `return` в `handleSubmit` (`if (state.status === 'pending') return`), а не HTML-дизейблом — именно так, как явно требует hooks-and-state.md §2 и задание (в тексте DoD в самой задаче написано «кнопка заблокирована», но конвенция и явная инструкция задания эксплицитно запрещают `disabled` на этой кнопке — приоритет отдан конвенции/явной инструкции, реализовано без `disabled`). `AbortController` — новый на каждый submit, предыдущий (если есть) отменяется перед новым запросом, и отменяется в cleanup `useEffect` при размонтировании страницы; `AbortError` в `catch` игнорируется молча (не показывается как ошибка пользователю). Пустой/пробельный промпт — клиентская валидация (`trim().length === 0`) до fetch, `aria-invalid`/`aria-describedby` на `<textarea>` + `role="alert"` на сообщении об ошибке (задокументированный выбор: клиентская валидация вместо похода на сервер за той же ошибкой). Скачивание — контракт §5 буквально («ответ конвертируется на клиенте в Blob»): `data.image` (data URL) конвертируется через `fetch(dataUrl).then(r => r.blob())` → `URL.createObjectURL(blob)`, результат используется и как `src` превью (`<img>`, обычный, не `next/image` — blob-URL несовместим с remote-оптимизатором, eslint-disable точечно на этой строке с комментарием) и как `href` кнопки скачивания (`<Button asChild><a href={objectUrl} download=...>`); предыдущий `objectUrl` освобождается через `URL.revokeObjectURL` при получении нового результата и при размонтировании (утечка исключена). `<main>` — landmark на странице (layout.tsx не даёт `<main>` сам, как и на других страницах, `app/q/[number]/page.tsx` для сравнения). Ровно один `<h1>`. Стиль — только существующие Material/shadcn-токены (`text-md-on-surface`, `border-md-outline/40`, `bg-md-surface-container`, `text-destructive`, `Button` из `components/ui/button.tsx`), новых цветов не добавлено. Проверка: `npm run typecheck` — 0 ошибок; `npm run lint` — 0 ошибок/предупреждений; `npm run build` — успешно, `/tools/image-generator` собран как статический (`○`) маршрут, единственные warning'и сборки — предсуществующие (`lib/illustrations.ts` fs-трейсинг, не связаны с этой задачей, см. заметки 9.4.1). Браузерное тестирование с интерактивными инструментами (клик/ввод текста/`read_console_messages`) недоступно в инструментарии этой сессии implementer — вместо этого: (1) `npx next start` + `curl` — SSR-разметка страницы проверена напрямую (h1 «Генератор изображений», `label[for=image-prompt]`+`textarea#image-prompt`, кнопка `type="submit"` без `disabled`); (2) полный сквозной прогон реального цикла клиента через Node (`fetch` с теми же заголовками/телом, что шлёт форма) против `POST /api/image-generator`: валидный промпт → `200 { image: "data:image/png;base64,..." }`, затем та же конвертация `fetch(dataUrl).then(r=>r.blob())`, что и в компоненте, — реально возвращает `Blob { size: 746355, type: 'image/png' }`, подтверждая, что клиентская логика превью/скачивания технически работоспособна; whitespace-only промпт → `{ error: "Введите текст запроса." }`, формат совпадает с тем, что читает `data.error` в компоненте.
