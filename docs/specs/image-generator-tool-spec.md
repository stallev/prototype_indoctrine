# Спецификация инструмента генерации изображений

Инструмент генерации изображений по текстовому промпту через xAI Grok Imagine (Vercel AI SDK) со скачиванием результата на ПК. Привязан к вопросам катехизиса через готовые промпты сцены (`prompts/grok-card-prompts-data.ts`) и опциональный оборот карточки; сам `POST /api/image-generator` по-прежнему принимает произвольный промпт и не читает `content/*.ts`.

**Статус:** предложено (ожидает утверждения)

## 1. Цель и границы

Пользователь вводит текстовый промпт (или выбирает вопрос — подставляется сцена), получает сгенерированную **лицевую** сторону, скачивает её. Опционально — **оборот** той же пропорции: ответ и первый стих, рисуются локально в Canvas, без вызова API и без записи в `public/illustrations/`.

Страница `/tools/image-generator` читает `content/*.ts` на сервере и передаёт в форму компактный словарь `{ answer, verse }` (клиент `content/*` не импортирует). Route Handler и ключи xAI к обороту не относятся.

| Входит | Не входит |
|---|---|
| Форма промпта → вызов Grok Imagine → превью лицевой → скачивание | Запись сгенерированных файлов в `public/` / S3 / БД |
| Выбор вопроса → готовый промпт сцены + Canvas-наложение текста на лицевую | Оборот через Grok / любой внешний image API |
| Оборот карточки: локальный Canvas, превью сразу при включённом чекбоксе | История генераций / галерея |
| Ключ API только на сервере | |

## 2. Расположение

- `app/tools/image-generator/page.tsx` — клиентский UI (`'use client'` для формы и состояния запроса).
- `app/api/image-generator/route.ts` — серверный Route Handler (Node runtime).

Доступен из `components/nav-drawer.tsx` (`components/nav-tools-link.tsx`) — отдельная ссылка «Генератор изображений» под списком разделов, визуально отделена (`border-top`) от навигации по катехизису и не читает `content/*`. Решение изменено по явному запросу пользователя (2026-08-21) — изначально инструмент планировался как несвязанная точка входа, обнаружилось, что без ссылки в меню он не обнаруживаем.

## 3. Серверная часть

- Route Handler принимает `POST` с телом `{ prompt: string, aspectRatio: string }`.
- Валидация входа: непустой промпт, ограничение длины, allowlist соотношения сторон.
- Вызов **Vercel AI SDK** в `lib/image-generator-generate.ts`: `@ai-sdk/xai`, модель `grok-imagine-image`, ключ `GROK_API_KEY`. Имя не стандартное для SDK (`XAI_API_KEY`), поэтому провайдер создаётся явно с `apiKey`. Ключ **никогда** не передаётся клиенту, не логируется, не попадает в ответ API. Отсутствие ключа — 500 fail-closed.
- Ответ — изображение в виде data URL (`data:${mediaType};base64,...`) плюс `estimatedCostUsd`.
- Ошибки провайдера (лимиты, невалидный промпт, недоступность API) — возвращаются клиенту как понятное сообщение, не как необработанное исключение/стектрейс.

## 4. Клиентская часть

- Форма: поле промпта, соотношение сторон, опциональное наложение текста вопроса (цвет из палитры, дефолт оранжевый `#FF8C00`), кнопка «Сгенерировать».
- Состояние ожидания (pending) на время запроса — кнопка НЕ получает HTML `disabled` (остаётся фокусируемой, сохраняет семантику активного элемента), вместо этого её содержимое меняется на индикатор ожидания (например, текст «Генерация…» + иконка спиннера); повторные клики/сабмиты во время pending игнорируются логически в обработчике `submit` (ранний `return`, если состояние уже `pending`) — соответствует `docs/conventions/hooks-and-state.md` §2 (не «замораживать» интерактивные элементы без обратной связи при async-переходах). Без оптимистичного UI (действие единичное, не список с мгновенной обратной связью).
- Результат: превью сгенерированного изображения (лицевая — после ответа API).
- Скачивание: ответ конвертируется в `Blob` на клиенте, скачивание — через `<a download>` по клику пользователя (обычное действие внутри приложения, инициированное пользователем).
- Ошибка — понятное сообщение в форме (текст/inline-алерт), без блокировки повторной попытки.
- **Оборот карточки** (локальный Canvas, `lib/card-back.ts`): чекбокс «Создать оборот карточки» активен только при выбранном вопросе. Превью появляется сразу (без Grok); смена вопроса или соотношения сторон перерисовывает оборот. Если лицевая уже есть — размер холста = `naturalWidth × naturalHeight`, иначе канонический размер из `canvasSizeForAspectRatio`. На обороте — ответ и **только первый** стих (`verse: null`, если стихов нет). Две кнопки скачивания: `q001-front.png` / `q001-back.png`. У оборота нет строки про себестоимость API. `POST /api/image-generator` не вызывается.

## 5. Влияние на деплой

Наличие серверного Route Handler с секретом означает, что всё приложение развёртывается как обычное Node-приложение на Vercel (`next build` + serverless/edge функции), а не через `output: 'export'`. Это единственная причина, по которой полностью статический экспорт невозможен — контентные страницы катехизиса (`/`, `/topic/*`, `/q/*`) при этом всё равно генерируются статически (`generateStaticParams`), сосуществование без конфликта.

## 6. Безопасность

- Ключ API (`GROK_API_KEY`) — только в переменных окружения сервера (`.env` локально — gitignored; переменные окружения проекта на Vercel для деплоя), никогда не коммитится; [`.env.example`](../../.env.example) документирует имя без значения.
- Rate limiting — не требуется в MVP-версии инструмента (личный/внутренний инструмент, не публичный сервис); зафиксировать как открытый вопрос, если инструмент станет общедоступным.
- Промпт пользователя не сохраняется на сервере дольше времени обработки запроса.

### 6.1. Доступ по общему ключу (`SECURITY_IMAGE_GENERATOR_KEY`)

Добавлено по явному запросу пользователя (2026-08-21) — простой gate на общем секрете, не полноценная многопользовательская авторизация (личный/внутренний инструмент, см. §6 выше):

- Отдельная от `GROK_API_KEY` переменная окружения — только на сервере, никогда не логируется и не попадает в клиентский бандл. `.env.example` документирует имя без значения.
- **Проверка ключа** — `app/tools/image-generator/actions.ts`, Server Action (запрошено явно пользователем): принимает кандидата, сравнивает с `SECURITY_IMAGE_GENERATOR_KEY` через `secretsMatch()` (`lib/image-generator-auth.ts`, `crypto.timingSafeEqual` по SHA-256-хэшам — устраняет и timing-атаку, и утечку через длину секрета). Клиенту возвращается только `boolean`, само значение ключа никогда не покидает сервер.
- **UI-gate** — `components/image-generator-access-gate.tsx` (`'use client'`, оборачивает `ImageGeneratorForm`). При открытии страницы: если в `localStorage` (ключ `image-generator-access-key`) есть сохранённое значение младше ~2 месяцев — оно сразу переотправляется на проверку Server Action'ом (ловит и протухание, и ротацию ключа на сервере); иначе — форма ввода ключа (`type="password"`). При успехе — значение сохраняется в `localStorage` с текущей меткой времени, форма генерации становится видимой.
- **Защита самого API-роута** — UI-gate сам по себе не защищает `POST /api/image-generator`: запрос с правильным `Origin` можно отправить в обход интерфейса. Поэтому `ImageGeneratorForm` отправляет тот же ключ (прочитанный из того же `localStorage`) в заголовке `x-image-generator-key`, а Route Handler обязательно сверяет его тем же `secretsMatch()` до вызова провайдера — `401`, если заголовок отсутствует/не совпадает; `500` (fail-closed), если `SECURITY_IMAGE_GENERATOR_KEY` вообще не задан на сервере.
- Осознанный компромисс: верное значение ключа хранится в `localStorage` в открытом виде до 2 месяцев — приемлемо для личного инструмента на доверенном устройстве, не для многопользовательского сценария с общим/публичным браузером.
