# Спецификация инструмента генерации изображений

Отдельный, самостоятельный инструмент генерации изображений по текстовому промпту через Google API (Vercel AI SDK) со скачиванием результата на ПК. **Не привязан к 114 вопросам катехизиса** и не использует `content/*.ts` — это отдельная утилита внутри того же Next.js-приложения.

**Статус:** предложено (ожидает утверждения)

Связанные документы:

- [`nextjs-migration-spec.md`](nextjs-migration-spec.md) — общая архитектура приложения, §8
- [`../contracts/image-generator-api-contract.md`](../contracts/image-generator-api-contract.md) — формальный контракт запроса/ответа этого роута
- [`../coding-conventions.md`](../coding-conventions.md) — конвенции безопасности/UI, применимые к этому инструменту
- [`../implementation/phase-9.4-image-generator-tool.md`](../implementation/phase-9.4-image-generator-tool.md) — задачи, реализующие эту спеку

---

## 1. Цель и границы

Универсальный инструмент: пользователь вводит текстовый промпт, получает сгенерированное изображение, скачивает его на ПК. Никакой связи с катехизисом, темами, вопросами или существующими SVG-иллюстрациями — инструмент не читает и не пишет `content/*.ts` или `public/illustrations/`.

| Входит | Не входит |
|---|---|
| Форма промпта → вызов Google API → превью → скачивание | Привязка к 114 вопросам/иллюстрациям катехизиса |
| Ключ API только на сервере | Хранение сгенерированных изображений (S3, БД, `public/`) |
| Один Route Handler, одна серверная функция | История генераций / галерея / повторное использование результатов |

---

## 2. Расположение

- `app/tools/image-generator/page.tsx` — клиентский UI (`'use client'` для формы и состояния запроса).
- `app/api/image-generator/route.ts` — серверный Route Handler (Node runtime).

Не связан ссылками с навигацией по катехизису (drawer, `/topic/*`, `/q/*`) — самостоятельная точка входа.

---

## 3. Серверная часть

- Route Handler принимает `POST` с телом `{ prompt: string }`.
- Валидация входа: непустой промпт, ограничение длины (защита от чрезмерно больших запросов).
- Вызов **Vercel AI SDK**, провайдер `@ai-sdk/google`, с ключом из переменной окружения **`GEMINI_API_KEY`** (уже добавлена в локальный `.env` — не стандартное имя, которое SDK ищет по умолчанию, поэтому провайдер создаётся явно с `apiKey: process.env.GEMINI_API_KEY`, см. `image-generator-api-contract.md` §4) — **никогда** не передаётся клиенту, не логируется, не попадает в ответ API.
- Конкретная модель Google (кандидаты: Gemini 2.5 Flash Image / Imagen) — фиксируется отдельным решением при реализации этого пункта; сама архитектура (server-only route handler) от выбора модели не зависит.
- Ответ — изображение в виде base64/data URL или бинарного потока (решается при реализации, в зависимости от формата ответа выбранного провайдера).
- Ошибки провайдера (лимиты, невалидный промпт, недоступность API) — возвращаются клиенту как понятное сообщение, не как необработанное исключение/стектрейс.

## 4. Клиентская часть

- Форма: поле промпта, кнопка «Сгенерировать».
- Состояние ожидания (pending) на время запроса — кнопка блокируется, показывается индикатор; без оптимистичного UI (действие единичное, не список с мгновенной обратной связью).
- Результат: превью сгенерированного изображения.
- Скачивание: ответ конвертируется в `Blob` на клиенте, скачивание — через `<a download>` по клику пользователя (обычное действие внутри приложения, инициированное пользователем).
- Ошибка — понятное сообщение в форме (текст/inline-алерт), без блокировки повторной попытки.

## 5. Влияние на деплой

Наличие серверного Route Handler с секретом означает, что всё приложение развёртывается как обычное Node-приложение на Vercel (`next build` + serverless/edge функции), а не через `output: 'export'`. Это единственная причина, по которой полностью статический экспорт невозможен — контентные страницы катехизиса (`/`, `/topic/*`, `/q/*`) при этом всё равно генерируются статически (`generateStaticParams`), сосуществование без конфликта.

## 6. Безопасность

- Ключ API (`GEMINI_API_KEY`) — только в переменных окружения сервера (`.env` локально — уже добавлен, gitignored; переменные окружения проекта на Vercel для деплоя), никогда не коммитится; [`.env.example`](../../.env.example) документирует имя переменной без значения.
- Rate limiting — не требуется в MVP-версии инструмента (личный/внутренний инструмент, не публичный сервис); зафиксировать как открытый вопрос, если инструмент станет общедоступным.
- Промпт пользователя не сохраняется на сервере дольше времени обработки запроса.

## 7. Открытые вопросы

1. Точная модель Google API (Gemini 2.5 Flash Image vs Imagen) и точный вызов Vercel AI SDK (`generateText` с `responseModalities` vs `experimental_generateImage`) — фиксируется на этапе реализации, требует проверки актуальной поддержки в установленной версии `ai`/`@ai-sdk/google`.
2. Нужен ли rate limiting/защита от злоупотребления, если инструмент будет доступен без аутентификации на публичном URL.
